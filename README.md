# Flowra

Локальное desktop-приложение для создания Telegram-ботов из блоков. Сценарии, файлы и данные пользователей хранятся на вашем компьютере. Регистрация и внешний сервер не нужны. Интернет требуется для Telegram и HTTP-запросов, которые вы добавите в сценарий.

Интерфейс на русском. Есть светлая, тёмная и системная темы. Приложение написано на Electron, React и TypeScript; редактор использует React Flow, база — SQLite.

## Быстрый запуск из исходников

Понадобятся Node.js **22.18 или новее** с npm, Git и Windows 10/11. Сборка проверяется на Windows. Конфигурация для Linux и macOS есть, но на этих системах приложение отдельно не проверялось. Python для самого Flowra не требуется.

Откройте терминал в папке проекта:

```sh
npm install
npm run dev
```

Откроется окно Flowra. Изменения интерфейса подхватываются автоматически. После изменения main-процесса, runtime или экспортера перезапустите команду.

Для запуска собранной версии:

```sh
npm run build
npm start
```

## Сборка приложения

```sh
npm run pack
```

Результат — папка `release/win-unpacked` с `Flowra.exe`. Её можно перенести целиком на другой компьютер. Установленный Node.js там уже не нужен.

Установщик и portable-версия для Windows:

```sh
npm run dist
```

Готовые файлы появятся в `release`. Сборки не подписаны цифровой подписью. Для публикации собственного релиза подпись настраивается отдельно.


## Первый бот

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram, отправьте `/newbot` и получите токен.
2. В Flowra нажмите **Создать бота**, укажите название и вставьте токен. Он проверяется методом `getMe`.
3. Откроется сценарий с блоками **Начало** и **Сообщение**. Выберите сообщение и измените текст справа.
4. Нажмите **Запустить**, откройте бота в Telegram и отправьте `/start`.
5. Во вкладке **Консоль** появятся события, во вкладке **Пользователи** — человек, который написал боту.

Можно оставить токен пустым и собрать черновик офлайн. Токен добавляется в настройках проекта; запуск и рассылки без него недоступны.

Токен хранится в SQLite в зашифрованном виде через Electron `safeStorage` — в Windows используется системное хранилище ключей. Токен не передаётся обратно в интерфейс, не сохраняется в workflow и не включается в экспорт. При переносе базы на другую учётную запись токен потребуется ввести заново. Не публикуйте папку данных приложения.

Один токен должен использоваться только одним запущенным экземпляром бота. Остановите бот на другом компьютере или хостинге перед запуском в Flowra. Если установлен webhook, удалите его методом `deleteWebhook` [Telegram Bot API](https://core.telegram.org/bots/api#deletewebhook). Flowra не удаляет чужой webhook автоматически.

## Редактор сценария

Слева находится список блоков. Нажмите на блок или перетащите его на поле. Соедините выход одного блока со входом следующего. Параметры выбранного блока открываются справа.

Поддерживаются перемещение, выделение нескольких блоков, масштабирование, перемещение поля, удаление, копирование, вставка, дублирование, отмена и повтор изменений. Сценарий сохраняется автоматически. Перед закрытием редактора приложение дожидается сохранения.

Горячие клавиши:

| Действие | Клавиши |
| --- | --- |
| Копировать выделенные блоки | Ctrl+C |
| Вставить | Ctrl+V |
| Дублировать | Ctrl+D |
| Отменить | Ctrl+Z |
| Повторить | Ctrl+Shift+Z |
| Удалить выделенное | Delete / Backspace |

Во время работы бот использует снимок сценария, полученный при запуске. Чтобы применить изменения к запущенному боту, остановите его и запустите снова.

### Доступные блоки

| Группа | Блоки |
| --- | --- |
| События | Начало `/start`, команда, сообщение, нажатие inline-кнопки |
| Telegram | Текст, фото, видео, аудио, голосовое, документ, геопозиция, контакт, опрос, викторина, медиагруппа, редактирование и удаление сообщения |
| Кнопки | Inline-клавиатура, обычная клавиатура, URL-кнопка |
| Логика | Условие, выбор по значению, задержка, случайная ветка |
| Данные | Переменная, запись переменной, чтение переменной, ввод пользователя |
| Сеть | HTTP-запрос: GET, POST, PUT, PATCH, DELETE |

У условия два выхода — `true` и `false`. У выбора по значению выходы соответствуют вариантам, а `default` используется, если ни один вариант не подошёл. Случайная ветка выбирает одну исходящую связь. Несколько обычных исходящих связей выполняются последовательно.

Блок ввода ждёт следующее сообщение и сохраняет текст, число, контакт или координаты в переменную. Команда `/start` начинает сценарий заново. Ожидание ввода и переменные сохраняются после перезапуска.

Кнопки отправляют собственное сообщение с клавиатурой. Для inline-кнопки выберите callback, ссылку или переход на конкретный блок. Обычная клавиатура поддерживает запрос контакта и геопозиции.

Опрос содержит от 2 до 12 ответов. В викторине нужно выбрать правильный ответ. Медиагруппа содержит от 2 до 10 фото/видео и отправляется одним альбомом. Проверки и ограничения собраны в `src/bot/media.ts` и обработчиках Telegram, а не распределены по интерфейсу. Актуальные ограничения описаны в [документации Telegram](https://core.telegram.org/bots/api).

### Переменные

В текстах и других строковых полях можно подставлять значения:

```text
Привет, {{user.first_name}}!
Ваш город: {{city}}
Координаты: {{location.latitude}}, {{location.longitude}}
```

Встроенные значения: `user.id`, `user.first_name`, `user.last_name`, `user.username`, `chat.id`. Пользовательские переменные доступны как `{{name}}` и `{{variable.name}}`. Данные каждого пользователя хранятся отдельно. Последний отправленный ID сообщения доступен как `{{last_message_id}}` для редактирования и удаления.

Пример знакомства: **Начало → Сообщение «Как вас зовут?» → Ввод в `name` → Сообщение «Привет, {{name}}!»**.

Условия сравнивают значения без выполнения пользовательского кода. Поддерживаются равенство, неравенство, вхождение, больше/меньше, больше/меньше или равно и наличие значения.

HTTP-блок принимает полный HTTP/HTTPS URL, заголовки, параметры запроса и тело. Заголовки и параметры задаются JSON-объектами. Ответ сохраняется в указанную переменную. Поля JSON доступны через точку. Запросы выполняются с вашего компьютера, в том числе к локальным сервисам.

## Файлы проекта

В медиаблоке нажмите **Выбрать файл**. Откроется системный диалог. Flowra проверит расширение и размер, скопирует файл в папку проекта и сохранит относительную ссылку вида `assets/<уникальное-имя>.png`. Исходный файл после этого можно перемещать.

Можно использовать также HTTP/HTTPS URL или Telegram `file_id`. Для альбома каждый элемент добавляется отдельно. Замена или удаление ссылки в блоке не удаляет файл с диска.

Раздел файлов показывает размер, тип и использование. Очистка удаляет только файлы, на которые больше не ссылаются сценарий и сохранённые рассылки. В экспорт попадают только файлы, используемые сценарием.

## Пользователи и сегменты

Пользователь появляется после первого входящего события. Повторный `/start` обновляет ту же запись. Сохраняются Telegram ID, chat ID, имя, username, язык, даты первого и последнего события, число событий, переменные и ожидающий блок ввода.

В таблице есть поиск, сортировка, страницы, просмотр и изменение переменных. Можно выгрузить выбранную аудиторию в CSV. Удаление записи очищает её локальные данные; если человек снова напишет боту, он появится заново.

Фильтры по языку, наличию username, датам активности и первому событию, а также наличию, равенству или вхождению переменной применяются через SQLite. Эти же фильтры используются для рассылки.

## Рассылки

Откройте **Рассылки**, выберите аудиторию и тип сообщения: текст, фото, видео или документ. Для медиа работает тот же выбор локального файла. Перед отправкой отображаются число получателей и подтверждение.

Аудитория фиксируется при создании рассылки. Отправка идёт через очередь, примерно по одному получателю в секунду. Очередь сохраняет результат для каждого получателя, общий прогресс и ошибки. Ошибка одного получателя не останавливает остальных. При Telegram `429` учитывается `retry_after`; заблокировавшие бота пользователи исключаются из следующих рассылок. В одном чате сообщение не дублируется, даже если в базе несколько пользователей этого чата.

Рассылку можно отменить. После завершения она остаётся в истории. Если закрыть приложение или процесс аварийно завершится, незавершённая рассылка получит статус **Прервана**. Автоматического возобновления нет: Telegram не предоставляет ключ идемпотентности для отправки, и повтор мог бы доставить сообщение дважды. Для новой отправки создайте новую рассылку с нужным сегментом.

Отдельные очереди по пользователям не позволяют задержке в сценарии одного человека остановить всех остальных. Ожидание внутри блока задержки не возобновляется после закрытия приложения; повторите нужную команду. Для постоянной работы держите приложение открытым или экспортируйте бот на сервер.

## Экспорт JavaScript / Node.js

Нажмите **Скачать** и выберите JavaScript. ZIP содержит:

```text
index.js
runtime.cjs
source/
workflow.json
package.json
.env.example
README.md
LICENSE
assets/
```

Распакуйте архив, установите Node.js 22.18+, скопируйте `.env.example` в `.env` и добавьте токен:

```text
TELEGRAM_BOT_TOKEN=токен_из_BotFather
```

```sh
npm install
npm start
```

Сторонние runtime-зависимости не нужны. Экспорт использует тот же движок, что и приложение, и встроенную SQLite Node.js. Файлы и база определяются относительно папки экспортированного проекта, независимо от текущей папки терминала.

В `source/` находятся исходники TypeScript и команда пересборки runtime: `cd source`, `npm install`, `npm run build`. Они входят в архив вместе с GPL.

## Экспорт Python

В том же окне выберите Python. Архив содержит `index.py`, `engine.py`, `api.py`, `storage.py`, `workflow.json`, `requirements.txt`, `.env.example`, `README.md`, `LICENSE` и используемые файлы `assets/`.

Понадобится Python 3.11+. Создайте `.env` с токеном, затем выполните:

```sh
pip install -r requirements.txt
python index.py
```

Используется стандартная библиотека Python, включая SQLite; `requirements.txt` не требует установки сторонних пакетов. Сценарий и все доступные типы блоков сохраняются при экспорте.

Оба варианта создают собственную SQLite-базу при первом запуске. Реальные пользователи и токен из Flowra в архив не попадают. Экспортируется исполняемый бот, без desktop-интерфейса управления и панели рассылок. Перед запуском экспорта остановите этот токен в Flowra.

## Где лежат данные

В Windows: `%APPDATA%/Flowra` (при запуске из исходников имя каталога может быть `flowra`). Точное место определяет Electron `app.getPath('userData')`.

```text
flowra.sqlite
projects/
  <project-id>/
    assets/
```

Для резервной копии закройте Flowra и скопируйте всю папку, включая SQLite и файлы проектов. Для отдельной тестовой базы можно задать переменную окружения `FLOWRA_DATA_DIR`. Дублирование проекта копирует сценарий и файлы; пользователи, история рассылок и токен в копию не переносятся.

## Структура исходников

```text
src/
  main/                 окно Electron, preload, IPC, файлы, процессы ботов
  renderer/             React-интерфейс и React Flow
  shared/               типы данных, проверка workflow
  database/             SQLite, миграции, запросы и сегменты
  bot/                  Telegram API, переменные, выполнение сценария
    handlers/           обработчики Telegram, данных и HTTP
  exporter/
    javascript/         входная точка standalone Node.js
    python/             standalone Python runtime
  assets/               иконка приложения
scripts/                сборка и запуск разработки
tests/                  проверки базы, файлов, runtime и экспорта
```

При сборке `resources/` получает standalone runtime и лицензию. Этот каталог генерируется автоматически. В renderer отключён Node.js; доступ к базе и файлам проходит через явные IPC-методы preload. У ботов отдельные utility-процессы. База использует WAL, foreign keys и параметризованные SQL-запросы.

### Миграции SQLite

1. `001`: проекты, настройки, пользователи, пользовательские переменные, рассылки и получатели; уникальность пользователя внутри проекта и индексы для сегментов.
2. `002`: локальные файлы, журнал приложения, история входящих событий и индексы.

Применённые версии записываются в `schema_migrations`. Миграции выполняются в транзакциях; существующая база не пересоздаётся.

Для ранней схемы Flowra с полем `bot_username` предусмотрен перенос: перед изменениями рядом создаётся полная резервная копия `flowra.sqlite.before-v1-<время>.bak`. Проекты, пользователи, переменные, файлы и история переносятся в новую схему одной транзакцией. Токены из ранних версий нужно ввести заново: их формат хранения мог отличаться. Исходная база с прежними токенами остаётся в резервной копии.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run test:desktop
npm run build
```

Тесты проверяют сохранение данных и миграции, сегменты, результаты рассылки, локальные файлы, обработку событий, переменные и ввод, Telegram payload, HTTP, retry, ZIP и запуск экспортированных точек входа. Telegram-транспорт в тестах заменяется тестовым HTTP-ответом; в production такой замены нет.

Без настоящего токена нельзя проверить доставку в Telegram, принятие конкретного фото/видео/голосового сервером, реальные ограничения и блокировку бота пользователем. Для этой проверки создайте отдельного бота в BotFather и отправьте ему сообщения. Не используйте рабочую базу и рабочую аудиторию для пробной рассылки.

## Если что-то не работает

- **Неверный токен.** Получите актуальный токен в BotFather и вставьте его целиком. Если токен раскрыт, отзовите его там же.
- **Telegram не отвечает.** Проверьте доступность `api.telegram.org` с этого компьютера. Ошибка отображается в интерфейсе и журнале.
- **Conflict / 409.** Остановите другие экземпляры этого бота. Для webhook используется отдельная ошибка с объяснением.
- **Бот не реагирует на новый блок.** Проверьте связи от события до блока, дождитесь сохранения и перезапустите бота.
- **Медиа не отправилось.** Проверьте формат, размер, существование файла и сообщение Telegram в консоли. Telegram может отклонять повреждённые файлы с корректным расширением.
- **Не подставилась переменная.** Проверьте имя с учётом регистра и пройдите блок ввода или записи переменной этим же Telegram-пользователем.
- **Нельзя расшифровать токен.** После переноса базы на другую систему или учётную запись введите токен заново.
- **Нужен SQLite в Node.js.** Используйте Node.js 22.18 или новее. На ранних версиях 22 SQLite экспериментальна и может выдавать предупреждение.
- **Ошибка npm install.** Проверьте доступ к npm registry и загрузкам Electron с GitHub. После исправления соединения повторите установку.

Позже можно добавить планирование рассылок, возобновление очередей с ручным выбором получателей, поиск по истории событий, проверку всего сценария перед запуском и установщики с цифровой подписью.
